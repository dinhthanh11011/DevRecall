## How to continue (from any new window)

1. `npm install && npm run validate && npm run progress`: see the current state below.
2. Pick the next item: a **track** whose status is `planned`, or `drafted` below target, in *Content stats*, or an unchecked box in *App features*.
3. Write content following `docs/CONTENT_GUIDE.md`, then run `npm run validate -- --track <id>`.
4. Run `npm run progress`, then add one line to the *Work log* (date, what, next).
5. Definition of done for a track: validator passes with no warnings, `status: drafted`, and `verify: true` on uncertain facts. It becomes `reviewed` only after a human fact-check.

## Notion corrections

Personal Notion notes found to be wrong or outdated while writing content (fix them in Notion when convenient):

- **Caching › Comprehensive Caching Guide for Senior Engineers**
  - Its table says Write-Through gives "Strong" consistency. In fact the DB write and the cache write aren't atomic, and racing writers can leave the cache stale, so it's closer to eventual (source: AWS Builders' Library, *Caching challenges and strategies*).
  - Refresh-Ahead is listed as "Strong". It's also eventual.
  - "Redis Cluster" is listed as a fix for cache avalanche. It doesn't fix mass expiry; TTL jitter, stale-while-revalidate and DB protection do.
- **Queues › Kafka**
  - "Consumer groups ensure no message is processed twice" is wrong. The default is at-least-once, so rebalances and crashes before a commit cause reprocessing.
  - `consumer.on('SIGTERM', …)` is wrong. It must be `process.on('SIGTERM', …)`; this is now debug question `messaging-kafka-048`.
  - "Kafka splits the data into partitions": the producer's partitioner chooses the partition.
  - The note misses KIP-848 (`group.protocol=consumer`, GA in Kafka 4.0) and Kafka 4.x share groups, which change the "extra consumers stay idle" rule.
- **Micro-Services › 13. Interview Questions (Comprehensive)**
  - E5 "REST: HTTP/1.1": REST isn't tied to any HTTP version.
  - "gRPC is 5–10x faster" has no source; it depends on the workload.
  - M16 "Production scale uses tail sampling" is overstated. Many systems use head sampling or a hybrid.
- **Web Security › HTTP / HTTPS - SSL/TLS**
  - The note teaches the RSA pre-master-secret handshake and "public key only encrypts". In TLS 1.3, keys come from ephemeral (EC)DHE, which gives forward secrecy. The certificate key only signs (CertificateVerify), and data is encrypted with a symmetric AEAD key (source: RFC 8446).
  - HTTP/1.1 pipelining isn't used by browsers, and HTTP/2 server push has been dropped by the major browsers.
- **Web Security › CORS**
  - "CORS lets the server specify which domains can send requests / prevents CSRF / blocks a cross-site delete POST" is wrong. CORS only relaxes the Same-Origin Policy so JS can **read** responses. Simple requests are still sent, with cookies if SameSite allows. CSRF needs SameSite cookies, CSRF tokens, and Origin/`Sec-Fetch-Site` checks (sources: Fetch Standard, MDN).
- **AWS (roadmap › Budget)**: "Unattached Elastic IP ~$3.60/month, free while attached" is outdated. Since 2024-02-01 every public IPv4 address is billed (~$0.005/hr) whether attached or not.
- **AWS Service Atlas › Route 53**: "7 routing policies" is outdated. There are 8; IP-based was added in 2022.
- **AWS Service Atlas › Multi-AZ vs Read Replica**: "the standby can't be read" is only true for a Multi-AZ *DB instance*. A Multi-AZ *DB cluster* has 2 readable standbys.
- **Backend › NodeJS (event loop)**: "nextTick/Promise run between phases" is wrong. Since Node 11 both queues drain after **each callback**. `process.nextTick` is also not a V8 microtask; it's a separate Node queue that runs before promises (source: nodejs.org event-loop guide).
- **Backend › NodeJS (worker_threads)**: "separate memory prevents leaks on the main thread" is misleading. Each worker has its own isolate/heap but runs in the same process, so it shares RSS and container limits and can use SharedArrayBuffer.
- **Backend › NodeJS (Express middleware)**: it doesn't warn that in Express 4, async rejections never reach the error handler without a wrapper (Express 5 fixes this).
- **Memory Leak**: "a never-resolving Promise can't be GC'd" is wrong. A pending promise with no references is collected; it only leaks when something retains it.
- **Backend › NestJS (lifecycle)**: the order is wrong. It should be Middleware → Guards → **Interceptors (before) → Pipes** → Handler → Interceptors (after) → Filters. Middleware *can* end the request, and a guard returning false gives a 403.
- **Backend › NestJS**: "built on Express / Express has no types". Nest supports the Express or Fastify adapter, and Express has @types/express.
- **TypeScript › Questions**:
  - `u = a` (any → unknown) compiles; it isn't an error.
  - `let c?: string` is invalid; `?` only applies to properties and parameters.
  - `age?: number` isn't equivalent to `number | undefined` under `exactOptionalPropertyTypes`.
  - `const empty = []` is an evolving array, not simply `any[]`.
- **Databases**: "update = delete old + insert new" is only roughly true for Postgres. MVCC writes a new tuple version, the old one becomes dead (VACUUM cleans it), and HOT updates skip index changes. It's wrong for SQL Server, which updates in place and uses the version store only with RCSI/SNAPSHOT.
- **Databases › SQL Databases**: "the PK index is usually clustered, and there's no separate heap" is true for SQL Server and InnoDB, **not Postgres**. Every Postgres table is a heap, every index points to a `ctid`, and `CLUSTER` reorders only once.
- **Search Engines › Elastic Search**: "primary shards can only change via reindex" is wrong; `_split` and `_shrink` exist. The routing formula uses `routing_num_shards`. A different `search_analyzer` is legitimate (autocomplete, synonyms).
- **Technologies › Browser SessionStorage**: "the storage event only fires for localStorage" is wrong. By spec it also fires for sessionStorage in same-session documents such as same-origin iframes. Minor.
- **Databases › NoSQL**: "DynamoDB = AP/eventual" is incomplete. It offers strongly consistent reads on tables and LSIs, but not GSIs.
- **Authentication › OpenID (OIDC)**: `nonce` is listed as a mandatory claim. It's only required when the client sent a nonce (and it's mandatory for implicit/hybrid). Q30: without the `openid` scope, no ID token is returned at all (source: OIDC Core 1.0 §2, §3.1.3.7).
- **Web Security › CSRF Protection**:
  - "SameSite means CSRF can't happen" is wrong. SameSite is defense in depth: Lax still sends cookies on top-level GET, and sibling subdomains count as same-site.
  - CSRF isn't cookie-only; Basic auth, client certs and IP-based auth are sent automatically too. The page also misses login CSRF.
  - "A custom header means no CSRF" only holds with strict CORS (source: OWASP CSRF Cheat Sheet).
- **Web Security › CSP**:
  - The "CSP in NestJS" snippet is actually Next.js middleware code.
  - `img-src 'self'` does NOT block a same-origin `/avatar.png`.
  - The page doesn't say that the meta-tag form ignores `frame-ancestors`, `report-uri` and `sandbox` (source: MDN).
- **Schedule Jobs**:
  - `runWithLock` releases the lock with GET then DEL, which isn't atomic. It should use a Lua compare-and-delete (source: redis.io distributed locks).
  - "A K8s CronJob won't run twice" is wrong. It may occasionally create 2 Jobs or none, so jobs must be idempotent (source: kubernetes.io).
- Web Security › RBAC is an empty page.
- **Frontend › ReactJS › Hooks**:
  - "Function components can't receive `ref`, so forwardRef is required" is outdated. Since React 19, `ref` is a normal prop.
  - Calling a setter inside another setter's updater (`setCount(prev => { setShowCongrats(true) … })`) is wrong; updaters must be pure.
  - The "unmounted component state update" warning was removed in React 18. The real reason for cleanup is race conditions and wasted work.
  - "useEffect always runs after paint" isn't always true: effects from discrete input can flush before paint (source: react.dev).
- **Web Security › Rate limit**: `express-rate-limit` now uses `limit`, with `max` kept as an alias (verify which version made the change). Minor.
- Technologies › DNS and Giải thuật › Độ phức tạp are empty pages, so there's nothing to check.
